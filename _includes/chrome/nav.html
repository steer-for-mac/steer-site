{#- Two affordances, not one overloaded glyph. The TRIGGER shows the appearance in force (sun or moon, picked by CSS from the resolved data-theme); the MENU shows which of the three was chosen. That split is the settled pattern -- shadcn and most current implementations do exactly this -- and it exists because no icon set has a glyph meaning "automatic, and it landed on dark". Lucide's eclipse and sun-moon both say "automatic" and stop there, which is what this button used to do: on a dark Mac you could see the site was following the system and still not know what the system had resolved to. A cycling button was the other option and is a known usability weakness: nothing on it can say what the next press will do. The menu says all three outright. Native popover, so open/close/light-dismiss/Escape and the top layer are the browser's. Radios rather than role="menuitemradio" for the same reason the controller picker uses them -- arrow keys come free and :checked is a fact CSS can read -- and consistency with that picker beats matching a different ARIA pattern in the same codebase. #}
